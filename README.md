\# Ciencia de datos

\### Desarrolla habilidades de programación reproducibles para ingesta, transformación, análisis y automatización de flujos de datos



\## Reglas generales



Cada unidad tiene una tarea individual, y todas trabajan sobre el dataset Car Sales de Kaggle.



&#x20;- Entorno. Trabaja siempre dentro del Dev Container (Codespaces o local). Si algo funciona solo fuera del contenedor, no cuenta como entregado.

&#x20;- Repositorio. Haz un fork de curso-datos y crea una rama por tarea, con el nombre unidad/<tu-usuario> . Habilita las Actions de tu fork (GitHub las desactiva por defecto).

&#x20;- Cómo se entrega. La unidad 1 se entrega con un pull request al repositorio del curso. De la unidad 2 a la unidad 4 se entrega con un pull request dentro de tu propio fork (de tu rama a tu main), y publicas el enlace al PR en el aula virtual. 

&#x20;- Datos. No subas al repositorio el archivo completo de Kaggle ni el archivo .duckdb. Para pruebas usa la muestra de unas mil filas que trae el repositorio. El dataset completo se descarga con el script de la unidad 2.

&#x20;- Secretos. Claves o tokens van en variables de entorno, nunca en el código ni en el historial de Git.

&#x20;- Corrección. Las Actions ejecutan ruff y pytest en cada PR. Luego el docente revisa a mano el PR, el código y el informe o la nota que se pida.

&#x20;- Ayudas externas. Puedes consultar documentación, foros y herramientas de IA. Declara en tu informe qué usaste y para qué, y asegúrate de poder explicar cada línea que entregas.

&#x20;- Plazos. Cada tarea tiene su fecha límite en el aula virtual. Los commits posteriores al plazo no se consideran.
